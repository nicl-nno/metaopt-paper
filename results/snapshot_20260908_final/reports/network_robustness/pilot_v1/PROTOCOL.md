# Ranking versus GNN regression for robust network design

Exploratory pilot, specified before pilot test outcomes on 7 September 2026.
This is a new benchmark implementation inspired by network-robustness literature;
it is not a reproduction of ResiNet or a claim of a new robustness measure.

## Problem and oracle

An individual is a connected, simple, undirected, unweighted graph. Double-edge
swaps preserve every vertex degree and the total edge count. Compared with the
source graph, at most `ceil(0.2 * number_of_edges)` new undirected edges are
allowed. Every intermediate proposal also obeys these constraints. The bound
counts new edges, not the number of mutation operations or changed endpoints.
The objective is to MAXIMIZE robustness:

`R = mean_scenario(sum(q=1..n, largest_component_size_after_q_deletions) / n^2)`.

Each attack deletes a node with maximum CURRENT degree, with exact updates after
every removal. Ties are resolved using the smallest random priority in a fixed
permutation. Four independently generated priority permutations form the primary
scenario bank for each source graph. The same bank is used for every candidate
and every method in that task. The primary objective is the exact value on this
finite bank, not a noise-free expectation over all tie permutations. Priorities
are independently generated between tasks and saved with offline data.

After all searches, every selected final network is re-evaluated on 32 NEW
priority permutations, common to all methods within the task. This sensitivity
check cannot select models or networks. Both finite-bank and new-bank effects
are reported. The latter can reveal overfitting to the primary tie scenarios.
Node identifiers/priorities and all attack outcomes are excluded from features.
Relabeling a graph together with its scenario priorities leaves its oracle value
unchanged; this property is tested.

## Source graphs and split

Two families: Barabasi-Albert with attachment parameter 3, and Erdos-Renyi G(n,m)
conditioned on connectivity with the same `m=3(n-3)` at a given size. Node counts
are 50 and 100. BA age labels are randomly permuted before use.

Each family/size cell contains 2 train, 1 validation and 2 test source graphs:
8 train + 4 validation + 8 test. Each train/validation task has 128 unique
candidates, including its source graph. This gives 1024 training and 512
validation oracle calls (6144 individual attack trajectories). Candidates are
generated by bounded random walks of feasible swaps from their own source graph.

ALL variants of a source graph remain in its split. No offline test fitness is
generated. The audit also checks that different source graphs are not isomorphic.
Different sizes in this pilot belong to both train and test; size extrapolation
is not claimed. The small task count is for a feasibility pilot, with no power
or confirmatory significance claim.

## Matched GNNs

The actual GAMLET `SimpleGNNEncoder` is reused through the existing
`RepositoryGraphSurrogate` adapter: three GraphSAGE layers, 32 channels, zero
dropout, a common task MLP and scalar head. Input dimension is adapted to six
node features: normalized degree, degree/mean degree, neighbor-degree mean and
standard deviation, clustering coefficient, and a constant. Context includes
size, degree statistics and allowed edit fraction. All features are available
without running the attack oracle. Feature construction is included in screening
time. Because degrees alone would remain constant across rewiring, neighborhood
statistics and message passing provide information about the changing topology.

Three losses use identical initial weights, candidate batches, Adam settings
and 60 epochs for each model seed (17, 23):

- `mse`: MSE on `1-R`, standardized separately within each training source graph.
  This equals regression on R after reversing the score sign.
- `log_mse`: MSE on `log(1-R)`, with the same normalization rule.
- `ranknet`: pairwise BCE on score differences; lower score means larger R,
  and exact ties receive 0.5. Pairs stay within a source graph.

All checkpoints minimize the same validation mean `log(best_pool_R/selected_R)`.
The main regression comparator is selected between MSE and log-MSE using mean
validation regret over model seeds, before any test search. All three results
remain visible. A pilot outcome cannot be used to silently replace this protocol.

## Search and controls

96 DISTINCT oracle evaluations, including the same 16 initial networks, per run.
The parent archive contains the 16 best truly evaluated networks. Each offspring
uses 1–3 feasible swaps. Surrogates screen 48 candidates and evaluate the best
three predictions plus one random remaining candidate. Surrogates remain frozen.

Controls: identical EA with four proposals and four evaluations, random selection
of four from the same size-48 evolutionary pool, single-swap local search around
the best evaluated network, and independent random walks from the source graph.
The local search is a simple control, not a reproduction of Smart Rewiring or a
state-of-the-art ResiNet comparator. Method execution order is randomized within
each task/search-seed block to reduce systematic timing drift.

Three search seeds (101, 202, 303), two model seeds and four model-independent
controls yield 240 searches: 23040 online oracle calls, 92160 online attack
trajectories, and 7680 extra final-validation attack trajectories. Reference
audits are separate and do not influence search decisions. Offline data,
training, online evaluation and screening times are recorded separately.

Primary response: ratio of final R for RankNet to the validation-selected GNN
regression under an equal true-evaluation budget. Average paired log ratios
over model/search seeds WITHIN source graphs first, then over source graphs.
Exploratory bootstrap intervals resample source graphs, conditional on the one
training set. They do not quantify variability over new training data.
Report fresh-scenario sensitivity, both individual regression comparators,
all classical controls, gains over initialization, and actual wall time.
No artificial oracle delays or claims about a known global optimum are used.

## Run

From the GAMLET repository root:

```powershell
& 'D:/agents/gamlet/.venv-gendesign/Scripts/python.exe' -m unittest discover -s experiments/network_robustness/tests -v
& 'D:/agents/gamlet/.venv-gendesign/Scripts/python.exe' -m experiments.network_robustness.experiment --config experiments/network_robustness/smoke.json --out experiments/network_robustness/results/smoke_v1
& 'D:/agents/gamlet/.venv-gendesign/Scripts/python.exe' -m experiments.network_robustness.experiment --config experiments/network_robustness/pilot.json --out experiments/network_robustness/results/pilot_v1
```

Use a new output directory for every run. Outputs include complete configurations,
source snapshots/hashes, task manifest, offline graphs/labels, checkpoints,
training histories, exact initial-population hashes, per-evaluation trajectories,
final graph edge lists, verification, summary and PNG/PDF figures. NetworkX
independently reproduces every primary attack trajectory on every saved final
network, plus one fresh scenario per final network. `COMPLETED.json` is written
only after search, fresh evaluation, audit and reporting succeed.
